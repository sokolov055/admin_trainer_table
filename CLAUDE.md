# Инструкции для Claude Code

Этот каталог — отдельный репозиторий фронтенда `sokolov055/admin_trainer_table`.
Основная ветка: `main`. Родительский каталог является другим репозиторием.

Перед работой выполни `git pull --ff-only origin main` именно внутри `webapp/`. Не коммить `.env`, `.env.demo`, `node_modules` и `dist`.

## Проверка и публикация

```bash
npm ci
npm run build
npm test
npm run test:e2e
```

`npm test` — все проверки, кроме браузерной; её же гоняет сборка. Отдельные
наборы (`test:workout`, `test:plan`, `test:ration`, `test:ration-access`,
`test:auth`, `test:preview`, `test:calendar`, `test:metrics`, `test:overview`, `test:push`, `test:offline`,
`test:browser`)
остались для быстрой отладки, но перед push запускай `npm test` целиком:
выбирать наборы глазами уже приводило к сломанной сборке.

`test:e2e` — настоящий браузер по демо-сборке: вход, программа, суперсет,
проведение тренировки, запись замера, чистая консоль. Требует Playwright и
Chromium (`npx playwright install chromium` после `npm ci`). Живых данных не
трогает: всё идёт по моку, поэтому проходить путь до конца можно смело.

После успешной сборки сделай коммит и push в `main`. Workflow `.github/workflows/deploy.yml` автоматически публикует GitHub Pages:

`https://sokolov055.github.io/admin_trainer_table/`

Переменная `VITE_API_URL` для production берётся из GitHub Actions secret. Не записывай секретные значения в исходники или workflow.

## Задача не выполнена, пока правки нет на странице

Зелёная сборка и успешный push этого не доказывают. Проверять — снаружи,
по живой странице, и только потом говорить, что готово:

```bash
base=https://sokolov055.github.io/admin_trainer_table
git rev-parse --short HEAD
curl -s "$base/index.html?n=$RANDOM" | grep -o 'content="[0-9a-f]\{7\}"'
```

Хеши совпали — выложено. Не совпали — сборка ещё идёт или упала, надо
дождаться и посмотреть.

Этого мало, когда менялся экран: `build-sha` говорит только о том, какой
коммит собрали. Возьми из `index.html` имя файла сборки и найди в нём
строку, которой раньше не было, — подпись кнопки, заголовок раздела:

```bash
asset=$(curl -s "$base/index.html?n=$RANDOM" | grep -o 'assets/index-[A-Za-z0-9_-]*\.js')
curl -s "$base/$asset" | grep -c "Вписать расход"
```

Можно и браузером — открыть страницу и посмотреть глазами; для экранов за
входом это единственный способ убедиться, что они рисуются, а не падают.

Отдельно помни: у человека правка появится не мгновенно. Сервис-воркер
отдаёт оболочку из кеша, поэтому первый запуск после выкладки может
показать прежнюю версию. Это нормально и не повод искать поломку — но и
не повод молчать: если правку ждут сейчас, скажи, что приложение нужно
закрыть и открыть заново.

После push проверь успешное завершение workflow `Deploy`. API на VPS разворачивается из соседнего основного репозитория по инструкции `../CLAUDE.md`; не копируй серверные секреты во фронтенд.

## Проведение тренировки (2.0)

`src/Workout.jsx` — общий экран для обеих ролей, открывается из `Plan`.
`workout-model.js` создаёт снимок программы; изменения относятся только к занятию.
Сохранение через `workout.save` с revision/requestId: сохраняй идемпотентность,
проверку конфликта и изоляцию черновиков по пользователю и карточке клиента.
Особенно важен запоздалый ответ после выхода с экрана: он не должен затереть
черновик уже открытого нового экземпляра. Сценарий покрыт тестом компонента.
Демо-журнал в `workout-mock.js` независим от продакшена, хранится локально.
Журнал и программы живут только в базе сервера (с 25.09 в Google Таблицы не
пишутся и оттуда не читаются); ни программа, ни касса при завершении занятия не
переписываются. За тренировками приложение не уходит на запасной Apps Script.

## Рацион из холодильника (3.0)

`src/nutrition/` — отдельная от остального приложения часть: `recipes.js`
(31 блюдо и справочник 56 продуктов, файл генерируемый), `match.js` (подбор,
сборка дня, список покупок — чистые функции без React), `Ration.jsx` (три
шага: холодильник, колода, день) и `ration.css`.

Сервер и Apps Script об этом разделе не знают: рецепты статические, а выбор
продуктов и «нравится» лежат в localStorage устройства. Правило про две ветки
API здесь не применяется — данные никуда не пишутся.

Счёт правится только в `match.js` и покрывается `npm run test:ration`: ошибка
в подборе ничего не ломает на экране, она просто предлагает съесть не то.
Тест сверяет и сами данные — КБЖУ каждого блюда пересчитывается из состава.

Вес продуктов: крупы и макароны сухие, мясо и рыба сырые; `per` — на порцию,
`items` — на весь объём блюда. Экран открывается только у клиента, в карточке
клиента у тренера его нет.

## Android-приложение

Оболочка живёт в `mobile/` основного репозитория и открывает эту же живую
страницу. Всё, что касается телефона (кнопка «Назад», цвет строки состояния,
ссылки в приложение), — в `src/native.js` и включается только при
`window.Capacitor`. Приложение — тоже WebView со строкой `; wv)`, поэтому
`detectBrowser` отличает его отдельно (`kind: installed`), а `isStandalone`
считает установленным. Правки веба доходят до Android без пересборки APK.
