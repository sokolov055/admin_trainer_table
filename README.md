# Мини-приложение тренера

Telegram Mini App поверх той же таблицы, что и раньше. Источник истины —
Google Sheets; приложение только читает их через Apps Script. Ничего не
дублируется, рассинхрону взяться неоткуда.

```
Telegram → фронтенд (статика) → Apps Script Web App → Google Sheets
```

Клиент видит свои показатели, план, прогресс и питание. Тренер — всех
клиентов, финансы, процессы, ушедших, логи и любой лист таблицы.

---

## Посмотреть без настройки

Демо-режим работает на вымышленных данных, Apps Script не нужен:

```bash
cd webapp
npm install
npm run dev -- --mode demo        # или: VITE_MOCK=1 npm run dev
```

Панель клиента — `http://localhost:5173/`
Панель тренера — `http://localhost:5173/?mockRole=trainer`

## Настройка целиком, по шагам

### 1. Развернуть Apps Script как веб-приложение

```bash
clasp push
```

Затем в редакторе Apps Script: **Начать развёртывание → Новое развёртывание →
Веб-приложение**.

- Запуск от имени: **я**
- Доступ: **Все**

Последнее обязательно: Telegram и браузер клиента приходят анонимно. Проверка
подлинности делается не доступом Google, а подписью `initData` — её проверяет
`100_ApiAuth.js` по токену бота.

Скопируйте выданный адрес вида
`https://script.google.com/macros/s/AKfy.../exec`.

### 2. Прописать токен бота

В таблице: **Приложение → 1. Настроить доступы Telegram**.

Токен берётся у [@BotFather](https://t.me/BotFather), секрет вебхука —
произвольная строка, её знаете только вы.

Токен хранится в Script Properties, а не в коде: репозиторий читают все, кому
дан доступ, свойства проекта — нет.

### 3. Узнать свой chat_id и стать тренером

Отправьте боту `/id` — он ответит числом. Это число впишите в
**Приложение → 2. Настроить мини-приложение**, поле «chat_id тренеров».

Кто в этом списке — видит админскую панель. Все остальные, привязанные к
карточке клиента, — панель клиента. Роль определяется только на сервере.

### 4. Собрать и опубликовать фронтенд

```bash
cd webapp
cp .env.example .env
# впишите в .env адрес из шага 1
npm install
npm run build
```

Готовая статика — в `webapp/dist/`. Её нужно положить на любой хостинг с
HTTPS. Telegram открывает мини-приложения только по HTTPS, `http://` не
подойдёт даже для проверки.

**Через GitHub Pages** (бесплатно): в репозитории **Settings → Pages →
Source: GitHub Actions**, затем добавьте секрет `VITE_API_URL` в **Settings →
Secrets and variables → Actions**. Workflow уже лежит в
`.github/workflows/deploy-webapp.yml` — он соберёт и опубликует при push в
`main`. Адрес получится вида `https://<логин>.github.io/<репозиторий>/`.

Подойдёт и любой другой статический хостинг — Netlify, Cloudflare Pages,
обычный nginx.

### 5. Связать всё вместе

Вернитесь в таблицу:

1. **Приложение → 2. Настроить мини-приложение** — вставьте адрес из шага 4.
   Заодно обновится кнопка меню в боте.
2. **Приложение → 3. Подключить вебхук Telegram** — адрес вебхука соберётся
   сам, руками ничего склеивать не нужно.
3. **Приложение → Проверить настройку** — покажет всю цепочку разом и укажет,
   какое звено ещё не готово.

### 6. Подключить клиентов

У каждого клиента на листе «Клиенты» должен быть заполнен `ClientKey`
(любая строка без пробелов) и ссылка на личную таблицу. Клиент отправляет боту:

```
/start ЕГО_КЛЮЧ
```

Бот запишет `TG_ChatId` в его строку и пришлёт кнопку запуска.

## Устройство проекта

| Файл | Что делает |
|---|---|
| `src/App.jsx` | спрашивает сервер «кто я» и выбирает панель |
| `src/api.js` | единственная точка общения с Apps Script |
| `src/telegram.js` | SDK Telegram: initData, тема, поведение окна |
| `src/charts.jsx` | линейный график на голом SVG |
| `src/ui.jsx` | плитки, значки, таблицы, состояния, форматирование |
| `src/client/` | панель клиента: обзор, план, прогресс, замеры, питание |
| `src/trainer/` | панель тренера: клиенты, финансы, процессы, ушедшие, логи, листы |
| `src/mock.js` | демо-данные, в обычную сборку не попадают |

Экраны клиента переиспользуются в карточке клиента у тренера — им просто
передаётся `clientRow`. Второй комплект «то же, но для тренера» пришлось бы
править дважды.

## Две особенности Apps Script, которые стоит знать

**CORS.** Apps Script не отвечает на preflight `OPTIONS`. Поэтому запросы
уходят с `Content-Type: text/plain`, хотя тело — JSON. Поставить
`application/json` — гарантированно получить ошибку CORS.

**Скорость.** Ответ занимает 300–1500 мс, это нормально для Apps Script.
Экран прогресса собран так, чтобы рисоваться одним запросом, а результаты
кэшируются на время сессии.

## Чего пока нет

- **Питание** — экран есть, данных нет. Включится сам, когда в личной таблице
  клиента появится лист «Питание» или на листе «Клиенты» — колонки
  Ккал / Белки / Жиры / Углеводы.
- **Запись из приложения.** Пока это витрина: всё редактируется в таблице.
  Первый очевидный кандидат на запись — рабочие веса в плане тренировки.
